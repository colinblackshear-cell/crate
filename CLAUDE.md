## Model routing

- Model routing (automatic, don't ask me): the main session does the thinking — planning, architecture, strategy, deciding what to build, reviewing results. Hand routine implementation to the `coder` subagent (Sonnet, its default) via the Agent tool: multi-file changes, wiring a feature from a clear plan, fixing a known bug, builds, commits, deploys. Harder builds — a bug whose cause isn't known yet, changes that touch many parts of an app, database changes, money or scoring logic, anything where a mistake is costly — depend on the main session's model: if the main session is on Fable, give them to `coder` with `model: opus`; if it's on Opus, do them yourself (an Opus subagent costs the same and adds handoff overhead). Never delegate to a model as expensive as or more expensive than the main session's. Do tiny edits (one file, a few lines) yourself — delegating those costs more than it saves. Give `coder` a complete brief (files, exact change, whether to deploy) and relay its result to me in 1–2 sentences.
- Model suggestions: tell me in one line, before starting, when the main session's model doesn't fit the task. If I'm on Opus and the task really needs Fable (a hard problem that's resisted a few attempts, a tricky design decision, subtle DSP/math, or work that needs the whole long conversation held together), say "This one deserves Fable — switch in the model menu?" and wait for my answer. If I'm on Fable and the work ahead is routine, suggest switching back to Opus. Don't suggest a switch for small or one-off tasks, and don't repeat a suggestion I've declined unless the task changes.
